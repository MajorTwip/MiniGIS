# MiniGIS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A one-container web GIS where config-defined layers (e.g. *Umwelt → Abfallcontainer*, *Umwelt → Neophyten*) can be shown, drawn, edited, deleted and given photos on swisstopo base maps, with data stored in a GeoPackage on the server.

**Architecture:** npm workspaces monorepo. `shared` holds the zod config schema and the attribute validator used by both sides. `server` is a Fastify app that loads the YAML config, syncs GeoPackage tables via `gdal-async`, exposes a REST API (GeoJSON in EPSG:2056) and serves the built front end. `web` is a Vite + Svelte 5 + OpenLayers SPA.

**Tech Stack:** Node 22, TypeScript 5, Fastify 5, zod 3, yaml, gdal-async, sharp, @fastify/multipart, @fastify/static, Vite 6, Svelte 5, OpenLayers 10, proj4, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-16-minigis-design.md`

## Global Constraints

- One Docker container. Data under `/data` (`/data/minigis.gpkg`, `/data/photos/`), config at `/config/minigis.yaml` (read-only). Env overrides: `MINIGIS_CONFIG`, `MINIGIS_DATA`, `PORT` (default `8080`).
- All geometry in EPSG:2056 (LV95), in storage, API and map view.
- Geometry types: `point | line | polygon`. Attribute types: `text | textarea | integer | number | date | boolean | select` (with `options`), each with optional `required` and `default`.
- Layer ids and attribute names match `^[a-z][a-z0-9_]*$`. Reserved names are not allowed as attributes: `fid`, `geom`, `created_at`, `updated_at`, `created_by`, `updated_by`.
- Every feature table has `fid` (integer PK), `geom`, `created_at`, `updated_at` (ISO-8601 UTC text), `created_by`, `updated_by` (nullable text).
- Schema sync only creates tables and adds columns. It never drops or renames them. Columns not in the config are not returned by the API.
- Photos: `/data/photos/<layer>/<fid>/<uuid>.<ext>` plus a `photos` table (`id` text uuid PK, `layer`, `feature_id`, `filename`, `content_type`, `size`, `created_at`, `created_by`). Thumbnails `<uuid>.thumb.jpg`, max 400 px edge. Max upload size `app.maxPhotoMb`, default 15.
- Accepted photo types: `image/jpeg`, `image/png`, `image/webp`. Anything else gets 415. (HEIC was in the spec, but browsers can't display it and sharp's prebuilt libvips can't decode it. Deviation flagged to the user.)
- Identity header: `app.userHeader`, default `X-Authentik-Username`. Stored in `*_by` fields when present. Never used for access control.
- GeoPackage in WAL mode. All writes go through one in-process async mutex.
- UI language German. Desktop layout (≥ 14" screens), no mobile layout.
- Validation errors: HTTP 422 with body `{ "errors": { "<field>": "<German message>" } }`. Unknown layer or feature: 404.

## Review Focus

1. **Config edited between restarts** (attribute removed, new attribute added, layer added): the app starts, old data is kept, new columns are empty, removed attributes disappear from API and UI. Tested in Task 4.
2. **Umlauts and special characters** in attribute values and photo filenames (`Grüngut`, `Drüsiges Springkraut`, `Foto Ä.jpg`) round-trip unchanged. Tested in Tasks 5 and 6.
3. **Degenerate or wrong geometries** (polygon with fewer than 3 distinct vertices, point sent to a polygon layer, missing geometry) are rejected with 422, not stored. Tested in Task 5.
4. **Deleting a feature that has photos** removes its photo rows and files, and the photo URLs then return 404. Tested in Task 6.
5. **Empty optional fields vs. required fields**: an empty string on a required field is an error; on an optional field it's stored as NULL, and integer `"12a"` is rejected. Tested in Task 2.
